`World Model`，中文通常叫“世界模型”。它的核心不是单纯生成一段视频，也不是把环境截图压缩成 embedding，而是让智能体拥有一种内部的 `mental model`：能根据已经看到的状态和将要采取的动作，预测世界接下来可能怎样变化。

人类做决策时经常依赖这种内部模型。比如过马路前会预判车辆轨迹；下棋前会在脑中推演几步；玩游戏时会猜测“如果我跳到这里，敌人会怎么移动”。世界模型试图把这种“想象、预演、再行动”的能力放进机器智能里。

这篇笔记重点整理基础架构，不追逐某一个最新产品。主线是：

- 世界模型到底建模什么。
- 它和 LLM 的 next token prediction 有什么关系和区别。
- 为什么世界模型通常要压缩到 latent space。
- 视频生成、3D 生成、JEPA、智能体训练分别在这个谱系里处于什么位置。
- 当前世界模型离真正可用的通用智能体还差什么。

## 一、什么是世界模型

最简单的定义是：

> 世界模型是智能体内部用于预测环境状态变化的模型。

如果把智能体和环境的交互写成一个循环：

{{< rawhtml >}}
$$
o_t \rightarrow a_t \rightarrow o_{t+1}
$$
{{< /rawhtml >}}

其中 $o_t$ 是当前观测，$a_t$ 是动作，$o_{t+1}$ 是下一步观测。那么世界模型想学习的就是：

{{< rawhtml >}}
$$
p(o_{t+1} | o_{\le t}, a_{\le t})
$$
{{< /rawhtml >}}

也就是：给定过去看到的东西和已经做过的动作，预测未来会发生什么。

但直接预测像素级的 $o_{t+1}$ 往往太难，也不一定必要。智能体真正需要的通常不是每个像素的精确值，而是和决策有关的结构：物体在哪里、速度如何、哪个区域可通行、哪个动作会带来奖励、哪些风险即将出现。

所以现代世界模型通常不在原始观测空间里工作，而是在一个压缩后的 latent space 里工作：

{{< rawhtml >}}
$$
z_t = e_\theta(o_t)
$$
{{< /rawhtml >}}

这里 $e_\theta$ 是 encoder，$z_t$ 是对当前世界状态的内部表示。模型再学习 latent dynamics：

{{< rawhtml >}}
$$
p_\theta(z_{t+1} | z_t, a_t)
$$
{{< /rawhtml >}}

这就是世界模型的基本骨架：

- `Representation`：把高维观测压缩成可用于推理的状态表示。
- `Prediction`：预测状态如何随时间和动作变化。
- `Planning & Control`：在内部模型中预演动作后果，再选择行动。

2018 年 Ha 和 Schmidhuber 的 `World Models` 论文给了一个很直观的三模块形式：

- `V`：vision model，把画面编码成 latent vector。
- `M`：memory model，用 recurrent model 预测 latent state 的时间演化。
- `C`：controller，根据 latent state 选择动作。

这套结构的关键思想是：智能体不一定要在真实环境里盲目试错，它可以先学会一个可压缩、可预测的“梦境”，再在梦境中训练策略。

## 二、从 MDP 到 Latent MDP

强化学习里常见的环境建模方式是 `MDP`：

{{< rawhtml >}}
$$
\mathcal{M}
=
(\mathcal{S}, \mathcal{A}, P, R, \gamma)
$$
{{< /rawhtml >}}

其中：

- $\mathcal{S}$ 是状态空间。
- $\mathcal{A}$ 是动作空间。
- $P(s_{t+1}|s_t,a_t)$ 是状态转移。
- $R(s_t,a_t)$ 是奖励函数。
- $\gamma$ 是折扣因子。

如果状态 $s_t$ 完全可见，问题会相对干净。但现实里智能体通常只能看到部分观测 $o_t$。例如摄像头只能看到当前视角，桌子背后的物体不可见；游戏截图只能显示当前画面，敌人的内部状态不可见；机器人传感器也会有噪声和遮挡。

因此更真实的建模方式是 `POMDP`。智能体无法直接拿到真实状态，只能从历史观测中推断一个 belief state：

{{< rawhtml >}}
$$
z_t
\approx
b(s_t | o_{\le t}, a_{\lt t})
$$
{{< /rawhtml >}}

世界模型里的 latent state $z_t$ 可以理解为这种 belief state 的神经网络版本。它不是对世界的完整拷贝，而是一个为了预测和控制而学习出来的内部摘要。

于是世界模型的底层范式可以概括成：

{{< rawhtml >}}
$$
\text{raw observation}
\rightarrow
\text{latent state}
\rightarrow
\text{latent dynamics}
\rightarrow
\text{planning / control}
$$
{{< /rawhtml >}}

如果写成训练目标，最朴素的形式是预测下一状态：

{{< rawhtml >}}
$$
\mathcal{L}_{dyn}
=
-
\log p_\theta(z_{t+1}|z_t,a_t)
$$
{{< /rawhtml >}}

如果还要服务决策，就会额外预测奖励、价值或终止信号：

{{< rawhtml >}}
$$
\begin{aligned}
\hat{z}_{t+1} &= f_\theta(z_t,a_t) \\
\hat{r}_t &= r_\theta(z_t,a_t) \\
\hat{v}_t &= v_\theta(z_t)
\end{aligned}
$$
{{< /rawhtml >}}

这也是 Dreamer、MuZero 这类方法的重要共同点：模型不一定复原完整世界，只要能预测和规划有关的变量，就可能足够有用。

## 三、世界模型的三层结构

可以把世界模型拆成三个层级看。

### 3.1 底层：模型底层范式

底层关心的是“世界如何被机器表示和推进”：

- `Latent MDP`：把原始观测映射到 latent state。
- `Learned Dynamics`：学习状态转移，而不是手写物理引擎。
- `Simulator`：在模型内部滚动未来轨迹，用于想象、规划或生成训练数据。

这一层最接近 model-based reinforcement learning。它关心的问题很工程：状态怎么压缩、转移模型怎么训练、误差如何随 rollout 累积、规划时怎么避免模型幻觉。

### 3.2 中层：世界的表示形式

中层关心的是“世界长什么样”：

- 视频生成：用连续帧表示世界变化。
- 3D 生成：用空间结构、几何、材质、物体关系表示世界。
- Object-centric representation：把世界拆成对象、属性和关系。
- JEPA 类方法：不重建像素，而是在 embedding space 预测未来或被遮挡部分。

这一层决定模型学到的是表面统计规律，还是更稳定的物理、空间和因果结构。

### 3.3 高层：智能体训练

高层关心的是“世界模型拿来做什么”：

- 训练策略：在模型生成的环境里练习。
- 辅助规划：在行动前模拟几种可能后果。
- 数据生成：构造现实中少见但重要的 edge cases。
- 任务泛化：让智能体迁移到没见过的新环境。

所以世界模型不是一个单独的生成模型标签，而是一整套面向智能体的架构思想。视频模型、3D 模型、强化学习模型、机器人仿真都可能成为世界模型的一部分，但只有当它们服务于预测、规划和行动时，才真正触及“世界模型”的核心。

## 四、和 LLM 的区别

LLM 和世界模型都在做 prediction，但预测对象不同。

传统自回归 LLM 的目标是：

{{< rawhtml >}}
$$
p_\theta(x_t | x_{\lt t})
$$
{{< /rawhtml >}}

也就是 next token prediction。文本序列本身就是训练和生成的主对象。

世界模型更关心：

{{< rawhtml >}}
$$
p_\theta(s_{t+1} | s_t, a_t)
$$
{{< /rawhtml >}}

或者在 latent space 中：

{{< rawhtml >}}
$$
p_\theta(z_{t+1} | z_t, a_t)
$$
{{< /rawhtml >}}

这里动作 $a_t$ 很关键。LLM 通常是在静态文本语料上学习“下一个 token 应该是什么”；世界模型则要学习“如果智能体采取某个动作，环境会如何响应”。

可以从四个维度对比：

| 维度 | LLM | World Model |
| --- | --- | --- |
| 预测目标 | next token | next state / frame / latent |
| 数据形态 | 文本、代码、网页等静态语料 | 视频、机器人轨迹、游戏交互、多模态传感器 |
| 时间结构 | 语言序列中的上下文依赖 | 物理时间中的状态转移 |
| 行动接口 | 生成文本或工具调用 | 选择动作并影响环境 |
| 核心难点 | 语义、推理、长上下文、对齐 | 部分可观测、因果、物理一致性、长期 rollout |

两者目标并不冲突。LLM 擅长语言、知识和任务分解，世界模型擅长环境预测和行动后果模拟。面向 AGI 或 embodied agent 的系统，很可能需要两者结合：

- LLM 负责理解指令、分解任务、调用工具和高层规划。
- 世界模型负责预测物理或虚拟环境的动态变化。
- Policy / controller 负责把计划落到具体动作。

这也是为什么很多智能体系统会把语言模型、视觉模型、动作模型和仿真模型组合起来，而不是只依赖单一 next token 模型。

## 五、如何表征世界

世界模型的关键分歧在于：到底预测什么。

### 5.1 像素级视频生成

视频生成模型可以被看成一种广义的 next frame prediction：

{{< rawhtml >}}
$$
p(x_{t+1}|x_{\le t})
$$
{{< /rawhtml >}}

如果加入动作条件，就变成：

{{< rawhtml >}}
$$
p(x_{t+1}|x_{\le t},a_t)
$$
{{< /rawhtml >}}

这条路线的优点是直观：模型直接生成未来画面，看起来像是在“想象世界”。大规模视频模型确实能学到很多隐式物理直觉，比如物体连续运动、遮挡关系、光照变化、相机运动等。

但视频生成不等于真正理解物理。它可能生成统计上合理的画面，却不保证：

- 同一个物体在长时间内身份一致。
- 物体质量、刚体约束、碰撞关系稳定。
- 动作和后果存在可控的因果关系。
- 生成世界可以被智能体可靠交互。

所以视频生成更像世界模型的感知外壳。它能提供丰富的视觉先验，但如果没有动作条件、状态记忆和可验证的动态一致性，就很难直接承担智能体训练的环境。

### 5.2 3D 和空间智能

3D 世界生成试图显式建模空间结构。相比纯视频，3D 表示通常更接近智能体需要的环境：

- 物体有位置、尺度、朝向和几何边界。
- 相机视角变化可以通过空间结构解释。
- 智能体可以在环境里导航、碰撞和交互。
- 场景可以被编辑、复用和模拟。

这也是“空间智能”路线的重点。以 World Labs 这类方向为例，核心野心不是只生成好看的图片，而是让模型理解三维世界如何组织，以及智能体如何在其中行动。

但 3D 路线也有现实困难：

- 高质量 3D 数据远少于图文和视频数据。
- 真实世界的材质、光照、流体、柔体和接触动力学很难精确生成。
- 可交互环境不仅要看起来合理，还要在动作后保持物理一致。
- 训练和渲染成本高，工程链路复杂。

所以 3D 表示更接近“可行动的世界”，但数据和仿真的门槛也更高。

### 5.3 JEPA：预测表示，而不是预测像素

JEPA 的思路是：不要把精力花在重建所有像素细节上，而是学习预测抽象表示。

一个典型结构可以写成：

{{< rawhtml >}}
$$
\begin{aligned}
z_c &= e_\theta(x_{context}) \\
z_t &= e_\theta(x_{target}) \\
\hat{z}_t &= p_\phi(z_c)
\end{aligned}
$$
{{< /rawhtml >}}

训练时让预测表示 $\hat{z}_t$ 接近目标表示 $z_t$：

{{< rawhtml >}}
$$
\mathcal{L}_{JEPA}
=
d(\hat{z}_t, z_t)
$$
{{< /rawhtml >}}

这里的关键是：模型不需要复原每个像素，只需要预测高层语义和结构。对于智能体来说，这可能更有效。因为很多像素细节是高熵噪声，比如树叶纹理、阴影细节、背景微小变化；它们对行动决策不一定重要。

JEPA 的世界模型倾向于学习：

- 物体和场景的抽象表示。
- 被遮挡区域或未来状态的语义结构。
- 时间变化中的稳定因素。
- 对下游任务有用的视觉特征。

这条路线强调“理解不等于重建”。一个模型可以不生成逼真的未来画面，但仍然学到对预测和行动有用的内部表示。

## 六、世界模型如何训练智能体

世界模型服务智能体时，最重要的用途是 `imagination`：在内部模型中预演未来。

给定当前 latent state $z_t$，智能体可以尝试多个候选动作序列：

{{< rawhtml >}}
$$
a_t, a_{t+1}, \dots, a_{t+H}
$$
{{< /rawhtml >}}

世界模型在 latent space 中 rollout：

{{< rawhtml >}}
$$
z_t
\rightarrow
z_{t+1}
\rightarrow
\cdots
\rightarrow
z_{t+H}
$$
{{< /rawhtml >}}

然后用预测奖励或价值评估这条轨迹：

{{< rawhtml >}}
$$
J
=
\sum_{k=0}^{H}
\gamma^k
\hat{r}_{t+k}
+
\gamma^{H+1}
\hat{v}(z_{t+H+1})
$$
{{< /rawhtml >}}

最后选择预期回报最高的动作。

这就是 model-based RL 的基本优势：真实环境交互很贵，但模型内部想象相对便宜。机器人摔一次可能损坏硬件，自动驾驶遇到一次极端事故代价很高，游戏或仿真里的失败则便宜得多。

### 6.1 Dyna：真实经验和模型经验混合

Dyna 架构是理解世界模型的一个经典入口。它把学习分成两部分：

- 从真实环境收集经验，更新策略和模型。
- 用学到的模型生成模拟经验，继续更新策略。

也就是说，智能体既从现实中学，也从想象中学。世界模型越准，想象经验越有价值；世界模型越偏，想象经验越可能误导策略。

### 6.2 Dreamer：在 latent imagination 中学习行为

Dreamer 系列把这一点做得很清楚：先学习一个 latent dynamics model，再在 latent space 中想象未来轨迹，并训练 actor-critic。

它的关键不是复原每一帧，而是让 latent state 足以预测奖励、价值和后续状态。这样策略可以在抽象空间中学习，效率比直接在像素环境中试错更高。

### 6.3 MuZero：只预测规划需要的东西

MuZero 更进一步：它不要求模型预测真实环境的完整状态，也不要求显式知道游戏规则。它学习三个函数：

- representation：把历史观测编码成 hidden state。
- dynamics：给定 hidden state 和动作，预测下一个 hidden state 与 reward。
- prediction：从 hidden state 预测 policy 和 value。

也就是说，MuZero 的模型是“为规划服务的模型”，不是“为还原世界服务的模型”。只要 hidden state 对搜索和价值估计有用，它就可以不对应人类可解释的物理状态。

这点非常重要：世界模型不一定要完整模拟世界。它需要足够准确地模拟和任务相关的世界。

### 6.4 SIMA：从虚拟世界走向通用行动

SIMA 代表了另一条更接近 embodied agent 的路线。它面对的是多个 3D 虚拟环境和商业游戏，输入是画面和自然语言指令，输出是键盘鼠标动作。

这类系统强调：

- 用多样化虚拟世界训练通用行动能力。
- 让语言指令和视觉环境对齐。
- 使用接近人类的操作接口，而不是依赖游戏内部 API。
- 在未见过的新环境中泛化。

SIMA 本身不等同于世界模型，但它说明了世界模型为什么重要：如果智能体要在复杂虚拟或真实环境中行动，它必须理解环境动态，而不是只会描述画面。

## 七、现实问题

世界模型很有吸引力，但也有几个基础难题。

### 7.1 部分可观测

智能体永远看不到完整世界。遮挡、噪声、隐藏变量和长期依赖都会造成不确定性。

例如一个球滚到墙后面，画面里已经看不到球，但智能体仍然应该记住它可能在哪里。世界模型必须维护 memory，而不是只根据当前帧预测下一帧。

### 7.2 长期 rollout 误差累积

一步预测准确，不代表多步预测可靠。模型内部 rollout 时，每一步的小误差都会进入下一步输入，最后可能偏离真实世界。

这会导致策略利用模型漏洞：在想象中某个动作很好，但现实中完全不可行。model-based RL 里这类问题很常见。

### 7.3 难以自监督地学到因果

视频数据里有大量相关性，但智能体需要的是因果性。看到物体移动，不等于知道“我的动作导致了它移动”。如果训练数据缺少交互，模型很难区分：

- 只是视觉上同时发生。
- 由环境自然演化导致。
- 由智能体动作导致。

所以真正用于行动的世界模型需要 action-conditioned data，也就是包含动作和后果的轨迹数据。

### 7.4 缺乏统一 benchmark

LLM 可以用 perplexity、MMLU、HumanEval、Arena 等指标粗略比较。世界模型更难评估，因为它的目标不是单一文本答案。

常见指标各有问题：

- 视频质量指标不等于物理一致性。
- 预测误差低不等于能帮助规划。
- 游戏分数高不等于能迁移到真实世界。
- 机器人任务成功率受硬件、环境和数据分布影响很大。

一个好的世界模型 benchmark 应该同时考察：预测、交互、长期一致性、可控性、任务迁移和规划收益。但目前这些维度还没有像 LLM benchmark 那样统一。

### 7.5 生成世界不等于可行动世界

很多模型可以生成看起来逼真的世界，但智能体未必能在其中训练。

可行动世界至少需要满足：

- 动作会稳定改变环境。
- 物体身份和几何结构长期一致。
- 物理约束不随时间漂移。
- 奖励、目标和失败条件可定义。
- 训练出的策略能迁移到真实或目标环境。

如果一个生成世界只能观看，不能可靠交互，它更接近视频模型；如果它能被智能体反复行动、试错、学习，它才更接近世界模型意义上的 simulator。

## 八、一个实用判断框架

判断一个模型是不是“世界模型”，可以问五个问题：

1. 它有没有内部状态表示？
2. 它能不能预测状态随时间变化？
3. 它的预测是否受动作条件影响？
4. 它能不能支持规划或策略训练？
5. 它的模拟结果能否迁移到真实或目标环境？

如果只有前两点，它更像普通预测模型。  
如果有前三点，它开始接近动态模型。  
如果有第四点，它可以服务智能体。  
如果第五点也成立，它才真正具备世界模型的工程价值。

所以世界模型的核心不是“生成一个世界”，而是“生成一个对行动有用的世界”。

## 九、小结

世界模型可以理解为智能体的内部想象系统。它把高维观测压缩成 latent state，学习状态如何随动作和时间变化，并用这种预测能力支持规划、控制和训练。

和 LLM 相比，世界模型的重点从语言序列转向环境动态，从 next token 转向 next state，从静态语料转向交互轨迹。视频生成、3D 生成和 JEPA 都可以成为世界模型路线的一部分，但它们只有在支持可控预测和行动学习时，才真正进入智能体架构的核心。

未来世界模型要解决的关键问题不是“画面能不能更真实”，而是：

- 状态表示是否稳定。
- 动作后果是否可预测。
- 长期 rollout 是否一致。
- 模型中的学习能否迁移到真实环境。
- 智能体能否借助它更少试错、更好规划。

从这个角度看，世界模型不是 LLM 的替代品，而是让语言智能走向 embodied intelligence 的关键组件。
